# 321Team

> 프로젝트 최종 인수 후 게시할 공개 소개문 초안입니다.

**321Team**은 하이브리드 클라우드 컨테이너 플랫폼 설계 및 구현 9기 과정의 프로젝트 팀입니다. 온프레미스와 AWS를 연결해 **이상금융거래 탐지 시스템(FDS)의 교육용 PoC**를 구축했습니다.

## 완성한 서비스

FDS는 정해 둔 규칙에 해당하는 거래를 찾아 위험 징후를 판단하는 시스템입니다. 거래 API가 요청을 받아 탐지 엔진에 판정을 요청하고, 거래 내역과 결과를 PostgreSQL에 기록합니다.

이번 결과물은 거래 판정과 근거 기록을 제공하는 교육용 PoC입니다. 실제 금융 거래 차단이나 금융기관의 운영 적합성 인증은 범위에 포함하지 않았습니다.

## 온프레미스에서 클라우드로

| 단계 | 구성과 목적 |
| --- | --- |
| Phase 1 | VM과 Kubernetes 기반의 온프레미스에 앱, 데이터베이스, 이미지 저장소와 배포 및 관측 기반을 구성했습니다. |
| Phase 2 | 두 앱을 AWS의 관리형 OpenShift 서비스인 ROSA로 확장했습니다. DB와 Harbor는 온프레미스에 유지하고, EC2 중계 서버와 Libreswan의 VPN으로 연결했습니다. |

기존 데이터와 이미지 공급 기반을 활용하면서 앱의 실행 환경을 확장했습니다. VPN으로 앱은 DB에 접속하고 노드는 Harbor에서 이미지를 내려받습니다. 사용자 접속과 VPN 연결, 배포 관리 경로를 구분하고, 배포 중 필요한 자원과 변경 조건도 함께 설계했습니다.

## 설계와 구현에서 중점을 둔 것

- **무결성:** 배포 대상과 이미지, 구성 원본을 대조할 근거를 남겼습니다.
- **재현성:** 패키지 버전과 구성 원본을 고정해 같은 입력을 다시 확인할 수 있는 기반을 마련했습니다.
- **추적성:** 배포 요청과 진행 단계, 사용한 원본의 이력을 남겨 변경 과정을 확인할 수 있도록 했습니다.
- **이식성:** 공통 배포 구성과 환경마다 달라지는 설정을 분리했습니다.

Trivy 검사에서 HIGH/CRITICAL 취약점이 나오거나 검사 자체가 실패하면 이미지 등록과 배포를 차단하도록 구현했습니다. TLS 인증서 검증과 최소 권한, 통신 범위 제한을 적용하고, 배포 결과가 불확실하면 추가 변경을 멈추도록 구성했습니다.
