# 321Team

**321Team**은 [코오롱 베니트] 하이브리드 클라우드 컨테이너 플랫폼 설계 및 구현 9기 과정의 프로젝트 팀입니다. 이 과정은 Red Hat과 AWS 환경을 기반으로 한 국비 지원 클라우드 부트캠프입니다.

이 페이지는 팀을 짧게 소개하기 위한 공개 프로필입니다. 내부 설계서, 실행 기록, 주소·인증 정보, 운영 절차는 공개하지 않습니다.

## 프로젝트

교육 과정에서 하이브리드 클라우드 컨테이너 플랫폼을 설계하고 구현한 뒤, 그 위에 **이상거래탐지(FDS)** 서비스를 올리는 팀 과제를 수행합니다.

공개할 수 있는 범위는 다음과 같습니다.

- 가상화 기반의 온프레미스 인프라와 컨테이너 오케스트레이션
- 거래 API(`transaction-api`)와 탐지 엔진(`fds-engine`)
- 서비스와 분리해 운영하는 PostgreSQL 데이터 계층
- 컨테이너 레지스트리, 취약점 점검, 모니터링, CI/CD를 포함한 플랫폼 구성

이 소개는 과정 과제와 팀 구성을 설명하는 글입니다. 상용 제품 출시나 운영 환경 인수 완료를 뜻하지 않습니다.

## 팀과 역할

역할은 내부에서 합의한 담당 영역을 공개용으로 정리한 것입니다. 개별 작업의 주 담당·지원 담당은 비공개 이슈에서 따로 관리합니다.

### 이하영 ([@hayeounglee](https://github.com/hayeounglee))

품질·문서 검증과 Kubernetes 구성을 맡습니다. 기준 문서와 변경안이 서로 맞는지 검토하고, 작성자와 분리된 시각에서 승인 의견을 남깁니다. 클러스터 구성, 네트워크 정책, 워크로드가 플랫폼에 올라가는 경로를 확인하고, 사실·추정·미확인을 구분해 시험이나 운영 결과를 문서 승인만으로 완료 처리하지 않도록 봅니다.

### 이재환 ([@supreme33-kr](https://github.com/supreme33-kr))

애플리케이션, 데이터, 모니터링, 시험(QA)을 맡습니다. 거래 API와 탐지 엔진, 데이터베이스 연동, 관측 구성, 기능·품질 확인을 중심으로 구현과 검증을 진행합니다. 기준 문서의 최종 승인·병합·발행은 담당하지 않습니다.

### 이권욱 ([@GWONUK](https://github.com/GWONUK))

기획 관리(PMO)와 인프라 구현, 기준 문서 운영을 맡습니다. 일정과 범위, 저장소 운영, 인프라·플랫폼 구축을 연결하고, 승인된 문서가 기준선으로 남도록 발행 절차를 관리합니다.

## 공개 범위

- 공개: 과정명, 팀 소개, 만들고 있는 플랫폼과 서비스의 개요
- 비공개: 내부 주소, 계정, 인증서, 비밀, 미공개 설계, 실행 로그, 작업 저장소
- 이 조직의 작업 저장소는 비공개이며, 조직 소개를 위해 공개한 저장소는 이 `.github` 저장소입니다.

문의는 각 구성원의 GitHub 프로필을 통해 남겨 주세요.
